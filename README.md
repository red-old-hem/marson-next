# マラソン逆算

出場するフルマラソンの日付を入れると、そこから逆算して最大18週間のトレーニングプランを組む iOS アプリです。

「意思が弱くても続く」ことを最優先に設計しています。記録の手間を極限まで減らし、完璧でなくても継続できる仕組みを入れてあります。

大会日固定版の [marathon-tracker-ios](../marathon-tracker-ios) を汎用化したものです。

## 特徴

### 大会日から逆算する

- **大会日を設定するだけ** — 大会名と日付を入れると、その日を最終週とするプランが組まれます
- **18週未満なら自動で圧縮** — 大会まで10週しかなければ10週プランになります。削るのは回復週とつなぎ週からで、30km走とロング走の柱は最後まで残します。調整期(最後の2週)は絶対に圧縮しません
- **日付付きの予定** — 練習可能曜日に各メニューを割り当て、画面と通知で共有します。本番は大会日に固定し、前日は空けます。利用可能日が足りなければ練習を減らします
- 大きく圧縮したときは「本来18週かけるプランです。きついならロング走を減らして構いません」と正直に伝えます

### 続けるための仕組み

- **ワンタップのチェックイン** — 走った日は1タップ。迷った日のための「5分だけ走った」ボタンを常設し、ゼロの日を作らないことを優先します
- **週2回の最低ライン** — 週3〜4回がベストでも「週2回できていれば達成」と定義。1回サボっても計画は崩れません
- **ヘルスケア自動チェックイン** — Apple Watch などのランニングワークアウトを読み取り、走った日を距離・時間つきで自動記録します
- **継続と練習完了を分離** — 自由ランも週2回の活動として数えます。練習メニューは、記録時または履歴画面でユーザーが選んだ予定だけを完了扱いにします。過去のメニュー文字列から完了を推測しません
- **通知** — 走る曜日・朝の時刻・夜の確認通知を設定できます。初回の設定保存時にだけ通知許可を確認します

### 季節に合わせた助言

大会日が変われば練習する季節も変わります。フェーズではなく**実際の暦月**から気候を判定し、夏なら「早朝か夜に走る。給水は我慢しない」、冬なら「最初の5分は歩くくらいゆっくり」といったメモを出します。春・秋は何も出しません。

食事アドバイスも同様で、レース3日前になると自動でカーボローディングの指示に変わります。

### 故障の予防

- **痛みの記録** — チェックイン時に部位をワンタップで記録できます
- **休養日も体調を記録** — 「今日の体調」から回答できます。未回答と「痛みなし」を区別し、自動記録だけで警告を解除しません
- **連続検知と休養推奨** — 同じ部位の痛みが2回続くと注意、3回以上で強い警告を出し、朝の通知も休養推奨に切り替わります
- **「痛みで休んだ」を達成扱いに** — 警告中は休養も週2回の最低ラインにカウントします。「休むとストリークが途切れる」設計だと、痛くても走ってしまい逆効果になるためです

### 記録の可視化

- **週別の走行距離グラフ** — 実績(棒)と目標(破線)を並べて表示。横になぞると週ごとの距離とペースが出ます
- **ペース表示** — 距離と時間からペースを自動算出します。ただし目標ペース(サブ4.5)は参照値として併記するだけで、達成/未達の判定はしません(このプランのイージーランは意図的に遅いため、常に「未達」と表示するのは逆効果です)

## 動作環境

- iOS 17.0 以降
- Xcode 16 以降
- [XcodeGen](https://github.com/yonaskolb/XcodeGen)

## ビルド方法

`.xcodeproj` は `project.yml` から生成するためリポジトリに含まれていません。

```bash
brew install xcodegen
xcodegen generate
open MarathonPlan.xcodeproj
```

Xcode で Signing & Capabilities からご自身の Team を選択して実行してください。

無料の Apple ID で実機にインストールした場合、署名が7日で失効するため定期的な再インストールが必要です。

macOS上では `swift test` で、Simulatorなしでも予定生成・保存復元・集計のテストを実行できます。

## 画面

- 今日: 当日の予定・チェックイン・体調・今週の活動
- プラン: 今週の予定とカレンダー
- 履歴: 記録、グラフ、実施メニューの確認
- 設定: 大会・プラン、練習曜日・通知、バックアップ・復元を別々に保存

## 設計上の注意点

コードを変更する際に壊しやすい不変条件があります。

1. **日付計算に `Calendar.current` を使わない** — 端末の暦法が和暦だとカウントダウンが壊れます。グレゴリオ暦固定の `Plan.calendar` を使ってください。`Calendar.dateInterval(of: .weekOfYear)` も `firstWeekday` がロケール依存なので使わず、`TrainingPlan.monday(containing:)` を使います
2. **`plan.weeks` を空にしない** — `TrainingPlan.clamped()` が範囲外アクセスでクラッシュします。`compressedWeeks` は必ず1要素以上を返し、`resolveStart` は大会週より後に `start` が来ないことを保証しています
3. **`RunLog` に追加するフィールドは必ず Optional にし、末尾に足す** — 合成 `Codable` は非Optional に `decode` を生成するため、デフォルト値があっても旧データの読み込みで throw します。読み込み時は1件ずつ部分復旧しますが、旧データ互換性を守るためこの規則を維持してください
4. **`km` は手入力専用** — ヘルスケア由来の距離は `autoKm` に持ち、表示は `distanceKm`(= `autoKm ?? km`)を使います。二重計上を防ぐためです
5. **ヘルスケア同期は種別を書き換えない** — 「5分だけ」「痛みで休んだ」を自動で「走った」に昇格させると、痛み警告が不当に解除されます
6. **`start` を毎日再計算しない** — プランが毎週1週ずつ縮みます。`start` は設定時に一度だけ決めて `RaceSetting` に永続化します

## 構成

| ファイル | 役割 |
|---|---|
| `Plan.swift` | 18週テンプレート、圧縮アルゴリズム、暦ユーティリティ |
| `TrainingPlan.swift` | 大会日から生成される実行中のプラン、`RaceSetting` の永続化 |
| `Season.swift` | 暦月からの季節判定 |
| `TrackerStore.swift` | 記録の保存・集計と、プランの保持 |
| `ScheduledSession.swift` | ID・日付を持つ練習予定の生成 |
| `TrackerRepository.swift` | バックアップ検証、状態ファイルの原子的保存、復元前の退避 |
| `TrackerScreens.swift` | 設定入口、当日予定、体調、記録履歴 |
| `Meals.swift` | 日付とフェーズに応じた食事アドバイス |
| `RaceSettingSheet.swift` | 大会日設定とオンボーディング |
| `ContentView.swift` | メイン画面の各カード |
| `DistanceChartCard.swift` | 週別走行距離グラフ(Swift Charts) |
| `HealthKitManager.swift` | ワークアウトの読み取りと自動チェックイン |
| `NotificationManager.swift` | ローカル通知のスケジューリング |

記録・大会・通知・体調は端末内の Application Support/MarathonPlan/state.json に状態全体として保存します。旧UserDefaults形式は初回に移行し、旧データも保持します。外部への自動送信は行いません。
「設定 → バックアップ・復元」から JSON を書き出し／復元できます。復元は全項目の検証と内容確認を経て反映し、「復元前のデータに戻す」で置換前へ戻せます。旧v1バックアップにも対応し、新規書き出しはv2です。
